moonctl reads a .api spec, a .proto file or a live database schema and writes the MoonBit around it: routes, types, handlers, typed clients in four languages, models and migrations. Change the spec and run it again — the files it owns are refreshed, the ones you wrote are left alone.

// Code generated by `mctl api ts` from a `.api` spec. DO NOT EDIT.

export class UserApiClient {
  readonly baseUrl: string;
  token?: string;

  constructor(baseUrl: string, fetchImpl?: Fetch, token?: string) {
    this.baseUrl = baseUrl.replace(/\/+$/, "");
    this.fetchImpl = fetchImpl ?? ((url, init) => fetch(url, init));
    this.token = token;
  }

  async login(body: LoginReq): Promise<LoginResp> {
    const path = `/api/v1/login`;
    const url = this.baseUrl + path;
    const headers: Record<string, string> = { accept: "application/json" };
    if (this.token !== undefined) {
      headers["authorization"] = "Bearer " + this.token;
    }
    const res = await this.fetchImpl(url, {
      method: "POST",
      headers,
      body: JSON.stringify(loginReqToJson(body)),
    });
    if (!res.ok) {
      throw new ApiError(res.status, await res.text());
    }
    return loginRespFromJson(JSON.parse(await res.text()));
  }
}

// Code generated by `mctl api dart` from a `.api` spec. DO NOT EDIT.

import 'dart:convert';

class UserApiClient {
  UserApiClient({required String baseUrl, required this.send, this.token})
      : baseUrl = baseUrl.replaceAll(RegExp(r'/+$'), '');

  final String baseUrl;
  final Send send;
  final String? token;

  Future<LoginResp> login(LoginReq body) async {
    final path = '/api/v1/login';
    final url = Uri.parse('$baseUrl$path');
    final headers = <String, String>{'accept': 'application/json'};
    if (token != null) {
      headers['authorization'] = 'Bearer $token';
    }
    final res = await send('POST', url, headers, jsonEncode(body.toJson()));
    if (!res.ok) {
      throw ApiException(res.status, res.body);
    }
    return LoginResp.fromJson(jsonDecode(res.body) as Map<String, dynamic>);
  }
}

class UserApiClient(
    private val baseUrl: String,
    private val transport: Transport,
    private val codec: Codec,
    private var token: String? = null,
) {
    fun login(body: LoginReq): LoginResp {
        val path = "/api/v1/login"
        val url = baseUrl + path
        val headers = linkedMapOf("accept" to "application/json")
        token?.let { headers["authorization"] = "Bearer " + it }
        val res = transport.send("POST", url, headers, codec.encode(body))
        if (!res.ok) {
            throw ApiException(res.status, res.body)
        }
        return LoginResp.fromWire(codec.decode(res.body))
    }

    fun getProfile(id: String): Profile {
        val path = "/api/v1/profile/" + enc(id)
        val res = transport.send("GET", baseUrl + path, linkedMapOf("accept" to "application/json"), null)
        if (!res.ok) {
            throw ApiException(res.status, res.body)
        }
        return Profile.fromWire(codec.decode(res.body))
    }
}

02 — Why

Generated, not scaffolded once.

Write the spec, generate, then go and write the part only you can write.

01

Regeneration is the normal case

Files the spec decides — routes, types, wire formats — are rewritten on every run. Handler bodies, logic and tests are written once and never touched again.

02

One parse, many outputs

Clients, models, docs and migrations come from the same spec tree. Rename a route and every output is renamed in the same run.

03

Nothing to install

The library is pure logic. Generated clients carry a transport port — fetch, a function, a class — instead of a runtime dependency.

04

Loud about bad input

A line the parser cannot read is an error with a line number, never a silently smaller spec. mctl api validate lists what is wrong before any code is written.

03 — Quick start

Three commands to a running shape.

A spec, a check, a project.

1 Write the contract

user.api
syntax = "v1"

type (
  LoginReq {
    Username string `json:"username"`
    Password string `json:"password"`
  }
  LoginResp {
    Token string `json:"token"`
  }
)

@server (
  prefix: /api/v1
  group:  user
)

service user-api {
  @doc "log a user in"
  @handler Login
  post /login (LoginReq) returns (LoginResp)
}

2 Check it

terminal
$ mctl api validate user.api
mctl: user.api is valid

$ mctl api format user.api --write
mctl: formatted user.api

04 — Commands

Every generator, one verb away.

A command and a file. The full surface is in the reference.

mctl gen api A moonapi service from a spec: routes, handlers, logic, config. mctl gen rpc A moonrpc service from a .proto, with messages and codecs. mctl api ts · dart · kt · java A typed client per route, in four languages, with no dependencies. mctl api doc A Markdown reference of the routes, groups and types. mctl migrate The SQL a spec's models imply, one table per type block. mctl model mongo Document models and typed repositories over a collection port. mctl gateway An HTTP front door in front of a .proto's RPCs. mctl quickstart Scaffold, generate and build a service in one step. mctl api validate Every finding, with a line number, before any code exists.
