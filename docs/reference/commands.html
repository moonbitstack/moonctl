Commands

One binary, mctl, and a verb for each thing it can write. Every generator takes a file and writes beside it unless --dir says otherwise.

The surface

CommandReadsWrites
mctl gen api <file.api>a speca moonapi project tree — or one file with --flat
mctl gen rpc <file.proto>a protoa moonrpc project tree: messages, codecs, handler table, client
mctl gen gql <file.api>a speca moongql schema and resolvers
mctl gen model <file.api>a spec<stem>_model.mbt — models and migrations
mctl gen crud <file.sql>DDL<stem>_model.mbt — models and typed CRUD
mctl gen doc <file.api>a specan OpenAPI document and a Swagger page
mctl gen agent <file.api>a speca moonkoog agent skeleton
mctl api format <file.api>a specthe canonical text, on stdout, or in place with --write
mctl api validate <file.api>a specthe findings, then a count — nothing on disk
mctl api doc <file.api>a spec<stem>_api.md — routes, groups, types, constraints
mctl api ts|dart|kt|java <file.api>a specone typed client per route, in that language
mctl migrate <file.api>a spec<service>_migrate.sql — one table per type block
mctl model mongo <file.api>a spec<service>_mongo.mbt — documents and repositories
mctl model cache <file.api>a spec<service>_cache.mbt — cache-aside CRUD
mctl model mysql datasource <dsn>a live MySQL schemamysql_model.mbt

Housekeeping

CommandWhat it does
mctl envprint the configuration in force and where each value came from
mctl config list|get|set|path|migrateread and write the config file
mctl template list|show [name]the bundled template catalogue
mctl completion <shell>a completion script for bash, zsh, fish or powershell
mctl upgrade [version]move the moonbitstack pins in moon.mod to a release
mctl bug [title]a bug report, pre-filled with the environment
mctl helpthe command table

Flags

FlagWhat it does
--dir <path>write the tree under path instead of here
--flatone .mbt file instead of a project tree
--style <template>how generated names are spelled: gozero, goZero, go_zero, …
--writerewrite the input file in place (api format)
--home <path>use this template home instead of the bundled library
--remote <url>read the template library from a git remote
--branch <name>the branch of --remote, main by default

The three library flags reach the configuration and the env report, but the generator still reads the bundled catalogue; see Configuration.

The template catalogue

TemplateSpecWhat it produces

rpc-serviceprotoa moonrpc service: messages, codecs, handler table and a client

model-mongoapidocument models over a Mongo collection, with a typed collection port
gatewayprotoan HTTP gateway that routes to a moonrpc client

The command prints the same rows as a Markdown table.

mctl template show api-service prints one entry; mctl template init writes the library into a directory to edit, and is not implemented yet.

The library behind it

Every command is a thin layer over an exported function, so a build script can do the same thing without a subprocess:

moon.pkg
import {
  "moonbitstack/moonctl",
}
FunctionWhat it returns
parse, parse_alla Spec from one file, or from a file and the sources it imports
generate, generate_treea scaffold as text, or as a tree of files
format, validate, validate_filesthe canonical text, and the findings for a spec
generate_client, client_filea typed client in one of four languages
generate_markdown, generate_migrationsthe Markdown reference, the migration SQL
generate_mongo, generate_cacheddocuments and repositories, the cache-aside layer
generate_gateway, default_routesthe gateway, and the routes a proto implies
generate_grpc, parse_protothe moonrpc service, and the proto tree it came from
generate_model, generate_crudmodels and the CRUD layer, from a spec or from DDL

The library is pure logic — a string in, a string out — so it runs on all four MoonBit targets, and a build step, a test or a browser page can call it.
