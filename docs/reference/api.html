Library API

Every public value, type and error in the library, package by package: what it takes, what it returns, and what it can raise.

Generated from the interfaces

scripts/gen_api_reference.py reads each src/*/pkg.generated.mbti — the interface moon info writes and moon check holds the source to — and the /// block above each declaration. Change a signature and this page changes with it; CI regenerates it and fails on a diff. An entry without prose has none in the source either, and is left bare rather than given a sentence invented to fill the space.

Using it #

The library is pure: a string in, a string out. Add the module, import the package, and call it from a build step, a test or a page.

main.mbt
let spec = @moonctl.parse(source)
let code = @moonctl.generate(spec)       // a moonapi scaffold, as text
let tree = @moonctl.generate_tree(spec)  // the layered project, file by file

The root package re-exports the types the other packages declare, so a caller can name @moonctl.Spec, @moonctl.Route and @moonctl.Template without importing anything else. Each re-exported type is listed under the package that owns it.

pub fn parse(String) -> Spec raise SpecError

Read a goctl-style .api description into a Spec. Grammar (one statement per line):

syntax = "v1"

info (
  title:   "greet"
  version: "v2"
)

type LoginReq {
  name: string
}

@server (
  group:      user
  prefix:     /api/v1
  middleware: Log
)
service greet {
  @doc "health check"
  @handler ping
  get /ping

  @handler login
  post /login (LoginReq) returns (LoginResp)

  get /legacy legacy_handler "the inline form"
}

A type block declares a message schema (its fields become a MoonBit struct); field types use goctl's Go spellings (string, int64, []T, map[K]V, …). An @server( … ) block annotates every route of the service block that follows it: the routes carry its prefix in their paths and its Group on their group. Verbs are lower-cased, blank lines and // comments are dropped.

Any other line raises a SpecError naming it — a misspelt verb or a missing brace would otherwise generate a quietly truncated program. Use parse_lenient for a best-effort read of a spec that is still being written.

pub fn parse_all(String, Map[String, String], from? : String) -> Spec raise SpecError

Parse source — the spec at from — together with everything it imports, taken from files (a map from resolved path to source, the shape deps resolves to). What the imports describe is merged in first, in the order they were declared, then the importing file's own: types, routes and @server groups all end up in one Spec. A file is scanned once however many times it is imported, so a cycle terminates.

The service name is the last one declared, so the importing file's own service block wins and a spec that does nothing but import still takes the name from what it imported.

An import naming a file that is not in files raises Missing; a file that does not parse raises its first complaint the way parse does, with the file it came from named alongside the line.

pub fn parse_lenient(String) -> Spec

parse without the diagnostics: a line the parser cannot read is skipped and whatever the spec does describe is returned. For a caller that generates from a half-written spec on every keystroke; anything that reports to a user should call parse.

pub fn resolve_import(String, String) -> String

An import path resolved against the file that declared it: taken relative to that file's directory, with ./.. folded away. An already-absolute path is left where it points.

pub fn to_i64(String) -> Int64?

s read as a non-negative decimal, or None when it is not one.

pub fn tokens(String) -> Array[String]

Whitespace-split a line into tokens, keeping a "quoted string" as one token (with the quotes stripped).

pub fn validate(Spec) -> Array[Diagnostic]

Check a parsed spec: the routes, the types and the places one names the other. Findings come in spec order — routes first, then types — so a report reads the way the file does.

pub fn validate_files(String, Map[String, String], from? : String) -> Array[Diagnostic]

Validate one file of a spec together with everything it imports, files being every source the walk has read keyed by the path it was read from. Without this a spec that embeds a type from another file is told that the type does not exist — true of the file on its own, false of the spec it belongs to.

pub fn validate_source(String) -> Array[Diagnostic]

Validate a spec given as source. A spec the parser cannot read is reported as the one finding it is — syntax, naming the line — rather than raising, so a caller checks a file the same way whether it is broken or merely wrong.

pub fn Style::parse(String) -> Self raise StyleError

Read a --style template. It must contain GO and then ZERO — in any case, with anything before, between and after them:

Style::parse("gozero").format("welcome_to_go_zero")  // welcometogozero
Style::parse("goZero").format("welcome_to_go_zero")  // welcomeToGoZero
